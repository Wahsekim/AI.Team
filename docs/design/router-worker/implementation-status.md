## Usage

From this worktree's repository root:

```sh
node --test tests/router-worker-compile.test.mjs
node scripts/compile-router-worker.mjs /absolute/path/to/owner-reviewed-input.json
```

To inspect the entirely synthetic fixture without creating a file:

```sh
node --input-type=module -e 'import { inputFixture } from "./tests/fixtures/router-worker/input.mjs"; import { compile } from "./src/router-worker/compile.mjs"; console.log(JSON.stringify(compile(inputFixture()), null, 2));'
```

The fixture is not an approved project configuration. Its commands are example
strings, never executed by the compiler. Runtime and approval references are
synthetic. No trial project or paid model is needed to run these tests.

## Contract and deliberate restrictions

The input has exactly `schemaVersion`, `ticket`, `mandate`, `proposal`, `catalog`,
`policy`, `baseline`. Version 1 remains supported for empty-method previews.
Version 2 adds the explicit selection fields below; unknown fields fail closed.

| Surface | Current behavior | Not yet proven / supported |
|---|---|---|
| Topology | Explicit `router-worker`, three distinct declared wrappers | Real registry, roster binding, independent sessions or actual tool enforcement |
| Tasks | Compiler accepts first exec/check only; anchored persistable journal models bounded retries and session continuity; `deliveryRequired: false` | Real host identity, compiler/host retry integration, actual continuation, non-code work and PM delivery |
| Methods | V1 empty methods; V2 optionally selects pinned `pstack-blast-radius` for check only | Exec methods, multi-method composition, arbitrary adapters or automatic skill selection |
| Scope | Planned paths and observed Git candidate changes must match both mandate and policy; grants allow exact paths or terminal `/**` | Exclusive ownership, ignored-file/external-effect enforcement and full protected-root policy |
| Tools | Requested exec tools must be in both allowlists | Runtime permissions; check/guard permission refs are declarations, not verified isolation |
| Risk | Declared risks, sensitive planned paths and observed sensitive changes are rejected pending a dedicated check | Security mapping and complete risk detection |
| Budget | Safe positive integers in `input+cache_creation`; exec + check + rework must fit ticket authorization | Real-time cap, guardian/PM run-level budget, usage settlement and account quota telemetry |
| Brief | No truncation; bounded UTF-16 size; preflight measures declared source bytes + brief against explicit ratchets | Semantic closure completeness, runtime-injected/Guardian prompt and exact tokenizer measurement |
| Digests | Inputs, plan, briefs, method pins; preflight resolves frozen local records and requires a separate approval-file anchor | Human approval authenticity/revocation, real Markdown-source adapters, approved compiler/host identity |
| Report | Report/candidate binding plus optional gate transcript/recipe consistency; real local command integration fixture | Trusted record origin, real session independence, project functional acceptance and settlement |

Methods cannot be passed as free text or serialized receipts to bypass the loader.
The task goal remains untrusted natural-language input; hashing and JSON framing
are not prompt-injection prevention. Only a future validated host can enforce
permissions and distinguish approved policy from caller-supplied assertions.

The preview baseline is not the eventual post-exec candidate. The new binding
library inspects that later candidate and can check supplied gate records, but
dispatch integration and independent model check execution are still pending. The check brief stops when
candidate binding is unavailable. Neither report shape nor report binding settles
a ticket.

## Version 2 method selection

Keep all version-1 fields, with these explicit changes:

- Set input `schemaVersion` and `policy.schemaVersion` to `2`.
- Set `catalog` to the exact local catalog returned by `methodCatalog(bundle)`.
- Add `policy.methodAllowlist` with `exec: []`, `check: ["pstack-blast-radius"]`,
  `guard: []`. An empty check allowlist is also valid but forbids selection.
- Keep `proposal.methodIds: []`; add `proposal.checkMethodIds` (empty or the
  single approved method) and `proposal.checkSelectionReason` (always required).
- Recompute `mandate.policyDigest` after an approved policy revision. Rehashing
  a policy does not itself constitute owner approval.

Library use separates read-only source resolution from pure compilation:

```js
import { loadMethods, methodCatalog } from '../../../src/router-worker/methods.mjs';
import { compile } from '../../../src/router-worker/compile.mjs';

const bundle = loadMethods();
const catalog = methodCatalog(bundle);
// Supply catalog in a complete, owner-reviewed v2 input; see fields above.
// compile(input, { methodBundle: bundle }) never loads or executes a skill.
```

The CLI automatically resolves its own local catalog for a nonempty v2 request.
It accepts no task-specified source root, adapter path or replacement renderer.
The loader reads only the fixed catalog/lock/source/license/adapter file set,
rejects symlink components and bounds file sizes. It does not import JavaScript
from catalog paths, fetch upstream, install tools, execute scripts or alter pins.
The executed adapter is the repository module, bound to its process-load digest.
The opaque in-memory bundle is not serializable dispatch authority.

The adapted method retains evidence-based impact review and explicitly includes
uncommitted candidate changes. It excludes unbundled `why`, `arena`, `unslop` and
multi-model orchestration instructions. Its retained dependency closure is the
locked SKILL.md plus the MIT license; removed dependencies are not silently
treated as installed. Source/license hashes, source-lock digest, adapter version
and digest, rendered-body digest and duty are included in the assignment receipt.
Only check receives its body; exec remains method-free.

The bundle is an immutable snapshot: later file edits cannot rewrite already
compiled content, and a fresh load detects changed bytes. This is not live
freshness checking or protection against a hostile process modifying the trusted
repository during module loading. Before real dispatch, RW-04 must revalidate the
approved bundle and freeze the complete launch inputs. Hashes establish local
consistency, not upstream authorship or owner authorization.

The fixed output digest test belongs to deliberate adapter adoption, not the
weekly upstream monitoring gate. Upstream drift can still be detected and
proposed through the existing PM-only update workflow; adopting it requires an
explicit catalog/lock/adapter review and updated fixture where warranted.
