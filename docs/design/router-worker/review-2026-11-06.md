# Router/Worker design review

Review date: 2026-11-06. English translation: 2026-11-10.
Subject: [design](README.md), then uncommitted on `codex/router-worker-mode`.
This preserves the historical review's conclusions; it is not a new approval.
The original language version remains in Git history. Later design responses and
implementation status may qualify findings below.

The reviewer checked repository claims before reviewing: the target fields exist
in `.claude/workflows/run-n-rounds.js`; the charter has eight Harness Rules;
`Tokens:` agrees with `scripts/measure-spawn.mjs`; and all three `probe.mjs` cases
match the design. The reviewer reported reading the Anthropic article and DeepSeek
prototype documentation/`policy.ts`, and found their use in the design accurate.

## Overall conclusion

The direction is sound: independent topology/bootstrap, coexistence with a clean
comparison against the old mode, and retained independent verification/governance.
Needed changes concern scope, wording and missing specifications, not the direction.

## Owner-decided boundaries

- A separate topology, not a generalist builder added inside specialist mode.
  Mixing rosters would confound attribution; the pilot needs two clean arms.
- Separate bootstrap so the new team can be tested without disturbing the old one.
- Integrate the optional branch, not replace the entire team. Both modes coexist;
  expansion depends on paired evidence.
- Borrow DeepSeek's Ticket/Mandate/Assignment/Report model and the rule that
  messages do not expand authority. Its research-prototype status is not deployment
  evidence for routing/execution.

## Strengths to retain

- Faithful, bounded use of both sources, without claiming proven cost savings.
- Separate topology, executionMode and dispatch axes; compile to existing engine
  parameters without changing the engine.
- The probe establishes that the existing validator accepts identical writer and
  verifier names.
- Explicit mapping of all eight Harness Rules, responsible duties and counting
  keys; deleting QA/Chaos rows is not a validator workaround.
- T0–T4 evidence levels, preregistered oracles, seeded defects with clean controls,
  repeated paired samples and alternating run order.

## Specifications that needed completion

1. **Rendered examples:** at least one brief and one Report to make RW-02 fixtures
   concrete.
2. **Vocabulary mapping:** connect Ticket/Mandate/Assignment/Report to tracker,
   brief fields, lifecycle NNN and close blocks.
3. **Mechanical security triggers:** path-based rules (for example auth/payments)
   require appropriate security checks instead of relying only on Router judgment.
4. **ADR:** consolidate owner-approved duty equivalence and boundaries rather than
   scatter them across sections 3, 7 and 11.
5. **Brief limits:** specify `MAX_BRIEF_CHARS`, context ratchets and permissible
   overflow handling for cross-layer briefs.
6. **Catalog model:** define where mode/duty/skill/policy allowlists, pins and
   digests live.
7. **Retry semantics:** one generalist's two retries cover the entire ticket,
   potentially tightening capacity compared with specialist roles; disclose this.
8. **Router predictions:** store expected scope, usage, methods and selection
   reasons on Assignment and compare at close for attribution.
9. **Known semantic gaps:** compiler validation does not prove scope completeness
   or strong acceptance criteria. There is no second Router review by default;
   that first-release tradeoff must be explicit.
10. **Generator equivalence:** retain zero-model generation and reuse mechanical
    bootstrap. Prioritize independent expected-output/manual-instantiation checks
    because paired comparisons depend on correct deployment generation.

## Document structure recommendations

- Concurrency reservations, migration and much of T2–T4 occupied roughly 40% of the
  reviewed draft while labelled out of first-release scope. Move future material
  to appendices/separate documents and keep RW-01–RW-05 prominent.
- Dense prohibitions obscure work items. Separate a bounded ADR, fixture-backed
  RW-01/RW-02 contracts and non-goals.
- State the actual experimental difference early: exec/check/guard resembles the
  MVT duty shape, but protocol plus task-selected methods fills duties instead of
  permanent job personas. That is the variable to measure.
- At review time, runtime role/charter/engine documents were English while the
  design was Chinese. Record the maintenance/operational risk. The Nov 10 language
  change addresses this presentation issue without changing authority.

## Router and drift

- Frozen scope, acceptance and budget define worker freedom; an incorrect boundary
  causes drift before execution starts.
- Separate a thin Router from a capable Router. Thin means PM does not implement,
  retaining the narrow read-only direct-verify exception after two procedural
  verifier failures. Capability comes from the roster's PM model setting and
  controlled wake context. Record PM cold-start size as a trial control variable.
- Test Router decisions themselves, including the prediction record above.

## Original recommendation outside this branch

The reviewer described same-name writer/verifier acceptance as a main-branch
preflight bug and recommended a separate `scripts/preflight-run.mjs` issue, not
expanding RW-02. This is the original review's characterization, not a newly
verified exploit. The subsequent design distinguishes name acceptance from proof
of same-session self-acceptance and calls for separate legacy contract/runtime
investigation before changing that path.
