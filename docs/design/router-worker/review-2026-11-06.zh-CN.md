# Router/Worker 设计评审结论

日期：2026-11-06。对象：[README.zh-CN.md](README.zh-CN.md)（分支 `codex/router-worker-mode`，未提交）。状态：评审结论，原文未改动。

评审前已核对方案对仓库的描述：编译目标字段在 `.claude/workflows/run-n-rounds.js` 中存在；charter 的 Harness Rules 为八条；`Tokens:` 刻度与 `scripts/measure-spawn.mjs` 一致；`probe.mjs` 可运行，三例结果与文中一致。两份来源（Anthropic 文章、DeepSeek 原型文档与 `policy.ts`）已通读，方案对二者的引用准确。

## 总结论

设计方向成立：独立拓扑、独立 bootstrap、与旧模式并存对照、保留独立验收与治理。待修的是文档的范围和表述，以及几处缺失的规格，不是方向。

## 已定的边界（owner 决定）

- 新模式是独立拓扑，不在 specialist 模式内以"加一个通才 builder"的方式实现。理由：混合 roster 无法归因试点结果，对照实验需要两条干净的臂。
- 需要独立 bootstrap，以便在不干扰旧设计的前提下独立测试新队伍模型。
- 分支融合，不整体融合：两种模式长期并存，是否扩大由配对证据决定。
- DeepSeek 原型借其域模型（Ticket/Mandate/Assignment/Report）和"消息不扩大授权"规则；其仓库自述为研究原型，不作为路由与执行部分的落地证据。

## 保留的优点

- 对两份来源的借鉴忠实且认清边界，明确文章未证明省钱。
- 拓扑、executionMode、派工机制三轴独立；编译到现有引擎参数，不改引擎。
- `probe.mjs` 是真实发现：当前校验器接受 writer 与 verifier 同名。
- 八条 Harness 规则逐条映射，标明责任人与计数键；"不能靠删 QA/Chaos 行过 validator"。
- T0–T4 分层证据、预登记 oracle、带干净对照的预置缺陷检验、交替顺序重复配对。

## 必须补的规格

1. **渲染样例**：至少一份编译后的 brief 和一份 Report，否则 RW-02 无 fixture 可写。
2. **词汇映射表**：Ticket/Mandate/Assignment/Report 分别对应现有 tracker、brief 字段、lifecycle NNN、close 块的哪些项。
3. **机械安全触发**：编译器按路径判定（如 auth、payments 目录下改动强制 security 档位 check），不只靠 Router 判断。
4. **ADR**：集中列出需要 owner 批准的职责等价映射与边界，不散在第三、七、十一节。
5. **brief 大小上限**：跨层 brief 受 `MAX_BRIEF_CHARS` 与上下文 ratchet 约束，写明上限和超限时的裁剪规则。
6. **catalog 数据模型**：`mode × duty × skill × policy` 白名单的存放位置、pin 格式、digest。
7. **重试上限语义**：按 ticket + duty 计数后，一个通才 worker 的两次重试覆盖整票，容量比专才模式收紧，需写明。
8. **Router 预测记录**：每个 Assignment 带 Router 的预测（预计改动范围、预计用量、所选 skill 及理由），close 时比对，使估算偏差、范围变更、skill 误选可归因。
9. **已知未覆盖项**：编译器只挡越权和缺字段，挡不住范围圈窄或验收写松；Router 目前没有第二双眼。首版可接受，但须列为已知未覆盖，不能默认被编译器覆盖。
10. **生成器等价测试**：对照结果依赖部署生成器正确。生成器保持零模型、复用原 bootstrap 机械实例化；RW-03 优先覆盖"生成结果与手工实例化等价"。

## 文档结构调整

- 第八节（并发预算预留）、第九节（迁移状态机）及第十节 T2–T4 的大部分，均标注首版不做，却占文档约四成。移到附录或独立文档，正文只保留 RW-01 至 RW-05。
- 禁令密度过高，实现者难以提取任务清单。拆为：带边界的 ADR、带 fixture 的 RW-01/RW-02 规格、非目标附录。
- 开头明说新旧模式的真实差异：职责形状（exec/check/guard）与 MVT 相同，差异在职责如何填充，即按 ticket 从通用协议加 skill 编译实例，而非固定 persona 常驻。这是试点要测的变量。
- 语言：实现代理读的角色文件、charter、引擎文档均为英文，设计文档为中文。列为已知操作风险。

## Router 与漂移

- Router 决定漂移：worker 的活动空间由冻结的 brief、验收和预算圈定，圈错即漂。
- "薄"与"聪明"分开落实：薄 = 不下地，沿用 PM 仅在 verifier 两次程序性失败后做只读 direct-verify 的既有规则；聪明 = roster PM 行的模型档位加受控的唤醒集大小。试点应记录 PM 冷启动上下文大小作为受控变量。
- Router 决策本身需被测：见上文第 8 条。

## 独立于本分支的事项

- writer/verifier 同名通过 preflight 是 main 当前的 bug，应对 `scripts/preflight-run.mjs` 独立立项，不留在 RW-02 范围内。
